## Data safety review

No model, repository, migration plan, photo storage, iCloud configuration, bundle identifier, entitlements or version number changed. History is a bundled read-only JSON resource. The only new persisted value is the local `showsTheatreHistory` preference. No new network service, analytics or permission prompt is introduced. Saving a card uses the existing Photos activity and its existing permission request.

## Scope limitations

Five events only, all Broadway openings. This is intentionally a starter catalog with an empty-day state and browseable archive. Broader geographic coverage and native-speaker editorial review should precede a growth campaign. Source URLs and dates were checked on 2026-10-13; production artwork is not bundled. No remote updates, notifications, historical claims generated by AI at runtime or personal diary matching.

## Reproduce

Open `StageLight.xcodeproj` from the feature worktree. Run `StageLightTests` and `StageLightUITests/TheatreHistoryUITests` on isolated iPhone and iPad simulators. The UI tests do not reset diary data, but should still use a dedicated simulator because they intentionally change the history visibility preference. Screenshots are retained as test attachments. The card renderer test attaches eight exports (four languages × two formats).

Initial red log: `/private/tmp/stagelight-history-red.log`.
Final iPad result bundle: `/private/tmp/history-ipad-final.xcresult`.
Final iPhone result bundle: `/private/tmp/history-iphone-verified.xcresult`.

UI tests verify that the Save to Photos action is available; they do not grant Photos permission or verify an asset was written. Photo-write implementation is reused without modification. A physical-device save smoke test remains appropriate before release.
